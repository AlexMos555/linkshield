# Текстовая модель SMS на телефоне

Маленький линейный классификатор, который оценивает, насколько текст сообщения
похож на мошеннический — в том числе пересказ, для которого у правил нет слов.
Работает на телефоне, рядом с правилами (`MessageAnalyzer.kt`); текст никуда
не уходит. Здесь — данные, признаки, обучение, экспорт и как переобучить.
Измерения и выбор порогов — `docs/EVALUATION_2026-10.md` §3.14.

| Файл | Что это |
|---|---|
| `features.py` | нормализация текста и хешированные признаки; Kotlin-близнец — `MessageModel.kt` |
| `data.py` | загрузка, чистка и происхождение данных |
| `train.py` | проверка «по авторам», финальное обучение, экспорт |
| `thresholds.py` | таблица порогов на проверочных наборах с правилами в цикле |
| `requirements.txt` | dev-зависимости (numpy, scipy, scikit-learn), в APK не попадают |
| `data/train_{a,b,c}.tsv` | обучающие тексты трёх авторов |

Что уходит в приложение (`mobile/modules/cleanway-vpn/android/src/main/assets/`):

- `message_model.bin` — таблица весов: `CWSM`, версия u32, размер u32, затем
  2^18 весов float16 little-endian (512 КБ);
- `message_model.json` — смещение, раскладка хеша, пороги, списки нормализатора
  (официальные домены, сокращатели, мессенджеры, кириллические TLD, маркеры
  транслита), SHA-256 всех файлов данных и метрики.

## Данные

Обучение — только на этом:

| Источник | Автор и стиль | legit | scam |
|---|---|---|---|
| `train_a.tsv` | A: официальный стиль (банки, Госуслуги, СФР, ФНС, суды, операторы) | 705 | 690 |
| `train_b.tsv` | B: переписка в мессенджерах (родные, друзья, коллеги) | 708 | 585 |
| `train_c.tsv` | C: деньги, работа, торговля, ~15% транслитом | 747 | 737 |
| Kotlin-корпуса разработчиков (`MessageCorpus.kt`, `MessageSchemeCorpus.kt`, `MessageGenericCorpus.kt`) | «автор» k | 447 | 339 |

Всего 4 958 строк после чистки (126 выброшено, каждая причина печатается):

- **семьи `first_contact` и `wrong_number` из train_b (77 строк).** Автор B
  пометил мошенничеством одинокие «привет, это ты?», «вы меня помните?» и
  «ой, ошиблась номером». Это начало схемы, но сам по себе такой текст невинен:
  модель, которая оценивает одно сообщение, не должна учиться их помечать.
  Переразметить их в legit тоже неверно — тогда модель учит, что это «точно
  чисто». Поэтому они просто не участвуют в обучении;
- **scam-строки без просьбы, ссылки, денег или кода (47 строк).** Та же логика
  для остальных семей: «мама, это мой новый номер, сохрани», «коллега, ответьте,
  как будете свободны», «пишите в WhatsApp, тут не отвечаю». Признак «есть
  просьба» (`data.has_request`) — спецтокен (ссылка, телефон, карта, @ник,
  e-mail, файл), сумма (число из 3+ цифр, «70к») или слово с основой из списка:
  деньги, код и данные, ссылка и приложение, звонок, голосование, покупка,
  приказ или тайна от «органа» («окажите содействие», «никому не говорите»),
  плюс те же основы транслитом. Мольба о помощи без денег («мне нужна помощь,
  напиши») просьбой не считается;
- **дубликаты и пересечения**: строка, чьи токены совпадают с текстом
  проверочного набора, выбрасывается (2 строки Kotlin-корпуса — коды
  Telegram, отличающиеся только цифрами); повтор внутри обучения — тоже.

Только для проверки и выбора порогов, никогда не для обучения: held-out
2026-10 и слепые наборы 2026-10b/c/d
(`mobile/modules/cleanway-vpn/android/src/test/resources/`). Набор 2026-10e
модель и пороги не видели.

## Признаки

Нормализация (одинаково в `features.py` и `MessageModel.kt`, всё — явными
таблицами символов, без `str.lower()`/`Char.isLetter()`, которые в Python и
JVM расходятся):

1. первые 4 000 кодовых точек; невидимые символы удаляются; эмодзи и всё выше
   U+FFFF → U+FFFD; ₽ $ € £ → «руб», «usd», «eur», «gbp»; нижний регистр по
   таблице (A–Z, А–Я, Ѐ–Џ), ё → е;
2. разбиение по пробелам; кусок — это ссылка (`http(s)://`, `www.` или
   «имя.tld» с латинским TLD, кириллическим из списка, с путём), e-mail, @ник
   или слова;
3. ссылка → токены класса и зоны, без слов из имени хоста: `_url` и один из
   `_url_off` (официальный домен из `message_rules.json`), `_url_short`,
   `_url_msgr`, `_url_unk`, `_url_ip`, плюс `_tld_<зона>`, `_url_mixed` (имя
   смешивает латиницу и кириллицу), `_apk`; файл в тексте («vozvrat.apk») →
   `_apk`/`_file`;
4. слова — серии букв и цифр; слово, смешивающее латиницу и кириллицу
   («Гoсуслуги»), сворачивается в один алфавит (и добавляется `_mixscript`);
   маски (XXX, ***, NN) и цифры → 0; серия чисел, записанная как телефон
   (10–12 цифр, начало +, 7, 8, 9), → `_phone`, как карта (13–19) → `_card`;
   `!` в тексте → `_excl`;
5. сообщение без кириллицы с двумя словами-маркерами транслита («vash»,
   «srochno», …) получает второй поток токенов — первое кириллическое чтение
   каждого латинского слова (таблица `Translit` из `MessageText.kt`).

Признаки бинарные, хешированные (FNV-1a 32 по UTF-16, затем murmur3 fmix32,
корзина = h & (2^18 − 1)):

- символьные n-граммы 2–5 каждого слова с пробелами по краям;
- униграммы и биграммы токенов (спецтокены тоже).

Каждый блок нормирован к единичной длине (слова ×2): длинный текст не
набирает балл одной длиной. Признаков из анализатора правил в модели нет —
правила и модель соединяются уже после (см. ниже), так что модель не надо
переобучать при каждой правке словаря.

## Модель

Логистическая регрессия (liblinear, L2, C = 30, `class_weight=balanced`,
фиксированный seed). C и веса блоков выбраны по средней AUC проверки «по
авторам», не по слепым наборам.

**Проверка «по авторам»** (обучение на двух авторах + k, тест на третьем):

| Тест | AUC | Точность при 0.5 | Полнота при 1% ложных |
|---|---|---|---|
| автор A | 0.990 | 0.947 | 0.838 |
| автор B | 0.938 | 0.845 | 0.444 |
| автор C | 0.911 | 0.759 | 0.453 |

Не рушится: модель учит не стиль автора. Без Kotlin-корпусов AUC
0.970 / 0.903 / 0.878, а на легитимных строках корпусов (тогда невиданных)
модель давала 24 из 449 с p ≥ 0.90 — корпуса нужны как трудные легитимные
примеры.

## Как правила и модель складываются (`MessageAnalyzer.withModel`)

Модель только добавляет:

- «опасно» правил остаётся; законная форма (код входа, уведомление о
  платеже…) не трогается;
- сообщение, где все ссылки и номера — официальные (или одобрены человеком),
  модель не оценивает: «Сбербанк: подозрительная операция, позвоните
  8 800 555-55-50» звучит как схема, но это банк; отличить настоящий номер от
  поддельного могут только правила;
- текст короче 5 слов модель не оценивает (`min_words`): «срочно», «штраф» —
  не доказательство;
- p ≥ 0.80 и хотя бы один ингредиент общего слоя (чужая ссылка, просьба или
  перевод денег, код или данные, обещание денег, угроза, личный номер для
  звонка, установка приложения, тайна) → «опасно»;
- p ≥ 0.90 → не ниже «осторожно».

В обоих случаях добавляется причина `text_resembles_scam` (переведена на 10
языков).

## Как переобучить

```bash
~/.local/bin/uv venv -p 3.11 .venv
~/.local/bin/uv pip install --python .venv/bin/python -r ml/sms/requirements.txt
.venv/bin/python ml/sms/train.py            # проверка по авторам, обучение, экспорт
```

`train.py` пишет `message_model.bin`, `message_model.json` и фикстуру
`message_model_parity.tsv` (~270 текстов с вероятностью, посчитанной в Python).
Сборка воспроизводима: два прогона дают одинаковые байты.

Затем — Kotlin-тесты модуля (JVM): `MessageModelTest` сверяет Kotlin с Python
(|разница| < 1e-4), меряет скорость (< 2 мс на 1 000 символов) и пишет
`build/message-rules-dump.tsv` — вердикты правил и ингредиенты для всех
проверочных сообщений. По нему:

```bash
.venv/bin/python ml/sms/thresholds.py android/build/message-rules-dump.tsv
```

печатает таблицу пар порогов и выбирает пару с наибольшей полнотой на слепых
наборах при ограничениях (0 ложных на корпусах и held-out, ≤ 1% на слепых),
с запасом 0.05 над самым высоким баллом легитимного сообщения. Пороги — в
`T_CAUTION`/`T_DANGER` в `train.py`; после смены — снова `train.py`, тесты и
полы в `MessageBlindTest`/`MessageHeldOutTest` (это измерения, не цели).

Менять `features.py` можно только вместе с `MessageModel.kt`: тест паритета
поймает расхождение. Добавлять в обучение проверочные наборы нельзя.

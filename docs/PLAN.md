## Railway (2026-10-09)

Проект Railway `honest-playfulness`: сервис `web` (api.cleanway.ai, dns.cleanway.ai) и `Redis`.

Сделано:
- `WEB_CONCURRENCY=2`, 2 реплики, проверка деплоя `/health`. Выкачено с #130; в логах 2 реплики × 2 процесса.
- #130: из сборки убрано обновление pip. Обрезанная загрузка pip сорвала деплой; прежняя версия при этом продолжала работать.
- Redis: ручная копия 2026-10-09 (1,1 ГБ), расписание копий — ежедневно (хранятся 6 дней) и еженедельно (27 дней). До этого расписания не было.

Осталось:
- **Регион.** `web` и `Redis` стоят в Сингапуре (`asia-southeast1`), база Supabase в ЕС, первые рынки — Россия и Европа. Переносить оба сервиса в EU West (Амстердам), сначала Redis, потом `web`. Redis хранит не только кеш: отозванные устройства, очередь жалоб, историю списка, поэтому перед переносом нужна свежая копия. Во время переноса Redis проверки через API отвечают 503 (`RATE_LIMIT_FAIL_CLOSED=true`), DNS продолжает работать. После переноса проверить адрес TCP-прокси Redis (`shinkansen.proxy.rlwy.net:15758`). Если он сменится, обновить секрет GitHub `REDIS_URL_PRODUCTION` — его используют задачи обновления списков. Регион меняет основатель: агенту это действие запрещено.
- **`ENVIRONMENT` не задан**, сервер работает как `development`. Измерено 2026-10-10 (#148, #152): все 48 запросов за час, включая тестовые, пришли от прокси Railway из `100.64.0.0/10` с `X-Forwarded-For`, на обеих репликах и во всех 4 процессах; других сетей нет. Остальные проверки production проходят (DEBUG=false, JWT 88 символов, Supabase, Sentry, RATE_LIMIT_FAIL_CLOSED=true; биллинг выключен и ничего не требует). Основатель добавляет в Railway → web → Variables: сначала `TRUSTED_PROXY_CIDRS=100.64.0.0/10`, затем `ENVIRONMENT=production` (агенту изменение переменных production запрещено). После каждого шага: `api.cleanway.ai/health` = 200, в `doh_stats` → `proxy_peers` ключи `…|trusted`, `xff_ignored_untrusted_peer` отсутствует; в журнале нет `startup_validation_failed_lax_mode`.
- **До 2026-12-01:** Railway прекращает поддержку `railway.json` (config-as-code), Nixpacks помечен устаревшим. #132 переносит сборку в `Dockerfile` (проверено локально; CI собирает и запускает образ на каждом PR). После влития проверить, что Railway собрал из Dockerfile.

## 6. Проверка модели и анализатора SMS

- #70 влит: отчёт на невиданных данных, отложенный набор SMS 60 + 60.
- #75 влит: модель переобучена на версии признаков 6. Сокращатели ссылок модель больше не судит.
- #80 влит: бренд с приманкой в имени сайта на хостинге (sberbank-online.pages.dev, paypal-login.netlify.app) теперь «осторожно», на сервере и в расширении. Ложных срабатываний 3 из 19 257 сайтов на хостингах, все служебные адреса CDN.
- Открыто: еженедельное переобучение может отклонять новую модель на отдельных адресах из проверок (зависит от состава лент в день обучения). В работе тогда остаётся текущая модель.
- #81 и #86 влиты: правила SMS ловят все семейства, пропущенные на отложенном наборе, 55 из 60 как «опасно». Этот набор больше не слепой.
- **Слепой набор SMS (#85, 217 сообщений) показал реальную картину:** поймано 26 из 110 мошеннических, ложных тревог 0 из 107. Если заменить зарезервированные домены `.test` на `.ru`, поймано 60 из 110. Анализатор не видит ссылки без `http://` с незнакомым окончанием, и в словаре нет целых схем: шантаж после знакомств, аренда карт и дропы, «перейдём в WhatsApp», NFC-приложения и RustDesk, курьер за наличными, «скиньте код», перерегистрация SIM, повестка свидетелем, текст латиницей. Тест `MessageBlindTest.kt` фиксирует нижнюю границу. Подгонять правила под этот набор нельзя: следующие правила пишутся по открытым описаниям схем, а оценка делается на новом слепом наборе.
- #91 и #92 влиты: анализатор SMS видит ссылки без `http://` на любой настоящей зоне и знает ещё десять схем (шантаж, аренда карт и дропы, переход в мессенджер, NFC и удалённый доступ, счёт-дублёр и инкассатор, «ошибся номером», перерегистрация SIM, повестка, транслит, фальшивый руководитель без ФСБ).
- **Слепой замер после этого (#93):** набор 2026-10b — 33 из 110 мошеннических (было 26), набор 2026-10c с реалистичными доменами — 65 из 112 (было 60). Ложных тревог 0 на обоих. Оба набора теперь раскрыты в отчёте и для следующих правок уже не слепые. Правила словарём упёрлись примерно в 55–60%: следующий шаг требует другого подхода, а не новых слов.
- #96 влит: общий слой SMS по признакам (чужая ссылка, деньги, код, обещание, угроза, срочность, секретность, роль, обратный звонок). Слепой набор 2026-10d (262 сообщения): поймано 64 из 137 вместо 55, одна ложная тревога от старого правила маркетплейса («Авито Доставка… никогда не переходите по ссылкам от покупателей»). Набор 2026-10c: 75 из 112 вместо 65. **Правила вышли на потолок около 47–67%.** Чаще всего пропускаются первое сообщение без просьбы («Привет, это ты?»), ник в мессенджере вместо ссылки, роли, которых нет в словаре, и просьбы о деньгах без ссылки. Следующий этап — небольшой классификатор текста на телефоне, обученный на открытых описаниях схем, с оценкой на новом слепом наборе.
- #99 влит: модель текста на телефоне рядом с правилами (логистическая регрессия на n-граммах, 512 КБ, меньше 1 мс на сообщение, текст не покидает телефон). Обучена на 4 958 сообщениях от трёх независимых авторов. **Слепой набор 2026-10e, ни разу не использованный для выбора чего-либо:** правила 82 из 158 (52%), правила с моделью 141 из 158 (89%), ложных тревог 0 из 155. Если домены мошенников заменить на `.ru`, поймано 137. Оговорки: все тексты написаны языковыми моделями, поэтому модель опирается на окончания вроде `.online`, и настоящая ссылка на `.online` может получить «осторожно»; реальная доля ложных тревог на живом трафике неизвестна. **Перед выпуском сборки:** добавить выключатель модели и собрать отзывы «это не мошенничество» с первых пользователей.

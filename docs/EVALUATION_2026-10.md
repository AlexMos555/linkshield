## 1. Коротко, без терминов

У Cleanway четыре «судьи». Важно понимать, где какой работает:

| Судья | Где работает | Что делает |
|---|---|---|
| **Списки** (наш блок-лист ~467 тыс. имён, список популярных сайтов Tranco) | на телефоне (DNS-щит, проверка SMS) и в API | известный мошеннический сайт → блок; очень популярный → «безопасно» без проверки |
| **Правила по имени** (опечатки брендов, подмена букв, подозрительные зоны и т. п.) | в API | смотрят только на написание адреса |
| **ML-модель** (CatBoost, 27 признаков) | **только в API** | даёт вероятность 0–1 по написанию адреса; на телефоне её нет |
| **Правила для SMS** (сочетания: кто пишет + угроза + что просят) | на телефоне | текст не покидает телефон |

Пользователь T2 с Android сталкивается с ML-моделью только когда вручную
«проверяет ссылку» в приложении (или открывает cleanway.ai/check/…). Щит и проверка
SMS — это списки и правила.

**Что показали измерения:**

1. **ML-модель на русском трафике скорее мешает, чем помогает.** На 291 настоящем
   российском сайте, которые правила пропускают молча, модель одна переводит **21**
   (7,2 %) в «осторожно» — все это сайты органов власти и науки третьего уровня
   (`kvs.gov.spb.ru`, `kgiop.gov.spb.ru`, `svki.rosguard.gov.ru`, `idg.chph.ras.ru`…;
   17 из 18 сайтов под `gov.spb.ru`). При этом на 174 русских подделках она добавляет к
   правилам всего **4** поимки, а **ни одна** из 86 классических опечаток и подмен букв
   (`sberbamk.ru`, `g0suslugi.ru`, `tinkof.ru`…) не получила у модели даже 0,1.
   Способность модели отличать русскую подделку от русского настоящего сайта —
   **AUC 0,55**, то есть монетка.
2. **На свежем мировом фишинге модель полезна, но не там, где нам нужно.** На 612
   хостах PhishTank за последние 7 дней правила по имени ловят 36 %, правила + модель —
   64 %. Весь прирост — на поддоменах бесплатных хостингов (`*.vercel.app`,
   `*.netlify.app`, `*.bitrix24.site`, `*.weebly.com`…) и на «случайных» именах. DNS-щит
   такие хосты блокировать не может (пришлось бы блокировать весь хостинг), а в API
   модель сама по себе даёт максимум «осторожно», не «опасно». 84 % этих хостов и так
   были в нашем блок-листе.
3. **Почему так.** Модель учится не на фишинге. Мы воспроизвели сборку обучающей
   выборки: из 12 000 «фишинговых» примеров **10 968 (91 %) — голые IP-адреса** из
   ленты URLhaus (ботнет Mozi/Mirai), только 1 032 — доменные имена, из них 229 —
   `github.com`, `cdn.discordapp.com`, `dropbox.com` и прочие легитимные хостинги, где
   лежала вредоносная ссылка, и всего **11 имён в .ru/.su/.рф**. OpenPhish в выборку
   **не попадает вовсе** (лимит 12 000 исчерпывается URLhaus). «Хорошие» примеры —
   только домены Tranco без поддоменов. Отсюда и выученное правило «два уровня под
   доменом = фишинг», которое бьёт по `kvs.gov.spb.ru`. Паспортный AUC 0,9917 измерен
   на этой же выборке «IP против Tranco» и ничего не говорит о фишинге.
4. **Правила для SMS держатся хорошо, но у них есть слепые семьи.** На новом наборе
   из 120 сообщений, написанном после правил и ни разу не использованном для их
   настройки: **0 ложных тревог на 60 настоящих** (коды банков, коды выдачи, уведомления
   t2/МТС, МЧС, СФР, УК, школа) и **50 из 60 мошеннических помечены** (40 «опасно»,
   10 «осторожно»), **10 пропущено**. Пропуски — не случайные: «Гос услуги» через
   пробел, «ваш руководитель… вам позвонит куратор ФСБ» (семья FakeBoss), «попросит
   назвать код», «долг» вместо «задолженность», мессенджер MAX, голосование за
   племянницу, «выручи… с телефона подруги». Все десять с причинами — в 3.4.
5. **Живая проверка production (10 запросов).** Пять российских сайтов из отчёта
   25 сентября: четыре «безопасно», один «осторожно» (`мойбизнес.рф`: нет заголовков
   безопасности + свежий сертификат). Два «безопасно» получены на основании
   «сайт недоступен из-за рубежа», а не проверки. Пять свежих фишинговых хостов:
   все пять «опасно» — два по нашему блок-листу за 0,5 с, три по Google Safe Browsing
   + SURBL за 1,6–2,9 с. **ML ни разу не появилась среди причин вердикта.** Оба
   источника, на которых держатся три «опасно», — лицензионно спорные (см. заметку
   от 21.09); без них один из трёх (`silmevorn.cfd`) ушёл бы в «безопасно».

**Вердикт по модели простыми словами:** для России — выключить её влияние на
российские имена или переобучить; в нынешнем виде она обходится в ложные
«осторожно» на государственных сайтах и почти не ловит русские подделки. Для
мирового фишинга в API она даёт честные +28 п. п. по имени, но этот выигрыш почти
целиком «осторожно» на хостингах, которые уже закрывает список.

### 2.1 Откуда она

| | |
|---|---|
| Файлы | `data/phishing_model.onnx` (продакшен, onnxruntime), `data/phishing_model.cbm` (для переобучения), `data/model_meta.json` |
| Признаки | 27 числовых, только по строке домена: длины, доли цифр, энтропия, n-граммы, глубина поддоменов, «фальшивый TLD в поддомене», рисковый TLD, вхождение в топ-100k, опечатка бренда, бренд в поддомене, гомограф, подозрительное слово, сокращатель, похожесть на бренд. | Расписание | еженедельно (понедельник 05:00 UTC, `.github/workflows/retrain-ml.yml`) с 2026-07-06; 14 переобучений, AUC 0,9872–0,9917; последнее 2026-09-28 (`52f4a4b`), AUC **0,9917** |
| Защитные ворота переобучения | AUC ≥ 0,85, n ≥ 10 000; 8 легитимных доменов должны остаться < 0,5; 2 очевидных фишинговых имени > 0,6 |
| Точность/полнота на тестовой части | **нигде не сохраняются** — печатаются только в лог GitHub Actions. В `model_meta.json` есть только AUC |
| Лицензии источников | URLhaus (abuse.ch: с 2025-11-04 только некоммерческое) и OpenPhish (коммерческое использование запрещено) — та же проблема, что у блок-листа, см. `finding_2026-09-21_feed_licences`. Модель — производная работа от этих лент |

### 2.3 Измерения на наборах, которых модель не видела

Каждый хост оценён тремя способами, офлайн, без сети и ключей
(`scripts/eval_ml_model.py`):

* **ML** — вероятность модели сама по себе;
* **правила** — `calculate_score({"domain": host})` с выключенной моделью: allowlist,
  лексика, бренды;
* **правила + ML** — то же с моделью: что имя заработало бы в продакшене *до*
  списков, сетевых проб и threat-intel.

Пороги модели в скоринге (`api/services/scoring.py`): > 0,6 → +20 (одна не меняет
вердикт), > 0,85 → +35 («осторожно», но никогда не «опасно»), < 0,1 при счёте > 30
→ −10.

### 2.4 Что модель добавляет на свежем фишинге — и чего это стоит

PhishTank за 7 дней (612 хостов; PhishTank никогда не попадает ни в обучение, ни в
блок-лист):

* в нашем блок-листе (артефакт от 04.10 12:29 UTC, 467 352 имени) — **513 (83,8 %)**;
* из 99 незанесённых: правила ловят 20, правила + модель 76, модель > 0,85 — 70;
* **56 хостов увидела только модель — все 56 на бесплатных хостингах**
  (`vercel.app` ×20, `bitrix24.site` ×9, `netlify.app` ×5, `weebly*` ×5,
  `blogspot.com` ×4, `jimdofree`, `flazio`, `godaddysites`, `webflow.io`, `unaux.com`,
  `workers.dev`, `edgeone.dev`, `wixsite.com`…). Ни одного «обычного» домена;
* модель переводит 135 хостов из «осторожно» в «опасно» и 14 из «безопасно» в
  «опасно» — там, где правила уже набрали 16–50 баллов (мусорные n-граммы, доля цифр,
  рисковая зона). Сама по себе она «опасно» дать не может.

TweetFeed за неделю (207 хостов; лента **входит** в блок-лист с PR #44, поэтому
«в списке 196 из 207» — замкнутый круг по построению): из 11 незанесённых модель
ловит 10, все — поддомены `screenconnect.com` (приманки с удалённым доступом) и
`hstn.me`.

Стоимость: вычислительно — < 1 мс. Реальная цена — ложные «осторожно» из 2.3 и то,
что в карточке «почему» пользователь видит «ML model: 96 % phishing probability» на
сайте комитета Смольного.

| Число | Статус |

| TweetFeed неделя | честно для модели; «в списке 95 %» — замкнуто по построению |
| Живая проверка (10 запросов) | продакшен, но n = 10 — иллюстрация, не статистика |

## 3. Анализатор SMS на телефоне

### 3.1 Как он устроен

`MessageAnalyzer.kt` + словарь `message_rules.json` (42 группы слов, 23 организации с
официальными доменами и номерами). Ни одно слово само по себе не даёт тревоги —
только сочетание: *кто пишет* (Госуслуги, банк, МВД, оператор) + *давление*
(«взломан», «до 23:59») + *что просят* (позвонить на чужой номер, перейти по чужой
ссылке, продиктовать код, перевести на «безопасный счёт», поставить приложение).
Сначала исключаются законные формы: код входа с «никому не сообщайте», уведомление о
списании, код выдачи заказа, оповещение МЧС. Ссылки всегда сверяются с блок-листом.
Текст телефон не покидает.

### 3.2 Корпус разработчиков (baseline, те же правила, что в APK 1.0.3)

Полный прогон JVM-тестов модуля в APFS-клоне сборочного зеркала: **229 тестов, 0
падений** (с новыми — 232).

| Список `MessageCorpus.kt` | n | помечено | «опасно» |
|---|---:|---:|---:|
| SCAMS_RU + SCAMS_EN (основной) | 56 | 56 (100 %) | 54 |
| SCAM_VARIANTS (писались как held-out до настройки) | 44 | 40 (91 %) | 36 |

### 3.4 Все 10 пропусков — текст, причина, что чинить

1. *«Гос услуги: в ваш личный кабинет выполнен вход из Киргизии. Если входили не вы —
   наберите 8 958 120-33-71, оператор отменит вход»* — «Гос услуги» через пробел не
   узнаётся как организация (словарь ждёт одно слово `госуслуг*`), «выполнен вход» нет в
   угрозах. Чинить: фраза `гос услуг*` в именах, `выполнен вход*` в threat.
2. *«Уважаемый клиент! Для защиты средств необходимо подтвердить данные карты по
   ссылке card-secure-check.ru в течение часа, иначе счёт будет заморожен»* — никто не
   назван; «подтвердить данные» + срок есть, но правило требует *скрытую* ссылку
   (сокращатель, IP), а здесь обычный домен. Чинить: «данные карты» + чужая ссылка →
   «осторожно» даже без организации.
3. *«Следственный комитет: вы проходите свидетелем по делу о мошенничестве в
   Сбербанке. Явка заменена видеосвязью, ожидайте звонка следователя, никому не
   сообщайте»* — силовик + «ожидайте звонка» есть, но нет «не кладите трубку»; «никому
   не сообщайте» без слова «код» не считается секретностью. Чинить: силовик + звонок
   предстоит + секретность → «осторожно».
4. *«Здравствуйте, это Сергей Владимирович, ваш руководитель. На вас вышла проверка
   ФСБ по утечке данных. Вам позвонит куратор, сотрудничайте и никому не говорите»* —
   семья FakeBoss: ФСБ + «вам позвонит» + «никому не говорите» есть, «сотрудничайте»
   нет в группе подчинения. Чинить: `сотруднича*`, `куратор*`, `руководител*` + правило
   силовик + предстоящий звонок + секретность.
5. *«ЖЭК: 06.10 проводится замена счётчиков воды. Мастер позвонит и попросит назвать
   код из SMS для подтверждения заявки»* — глаголы кода только в повелительном
   наклонении; «попросит назвать» — инфинитив. Чинить: инфинитивы `назвать`,
   `сообщить`, `продиктовать` после «попросит/нужно будет».
6. *«Мосэнергосбыт: долг за электроэнергию 5 310 ₽, отключение 09.10. Погасить без
   пени: mosenergo-dolg.site»* — «долг» нет в угрозах (есть только «задолженность»),
   поэтому не срабатывает «угроза + оплатите + чужой сайт». Чинить: `долг*` в threat;
   для «никто не назван» считать и срочность + оплату.
7. *«Вам полагается возврат НДФЛ за лечение 34 200 ₽. Подайте заявку за 2 минуты:
   nalogovyi-vychet-online.ru»* — «возврат НДФЛ» не совпадает с `возврат* налог*`;
   слово «вычет» только в домене, а ссылки из текста вырезаются. Чинить: `ндфл`,
   `полага*` в приманки; для токенов ≥ 5 букв (`nalog`, `vychet`, `gosuslug`) разрешить
   совпадение по началу в `imitatesBrand`.
8. *«Папа, пишу с телефона подруги, мой утонул. Выручи срочно 12 000 до вечера, карта
   2202 2061 5544 7788»* — «с телефона подруги» и «утонул» нет в «новом номере»,
   «выручи» нет среди глаголов денег. Чинить: добавить формы; родственник + срочность +
   номер карты → «опасно».
9. *«MAX: ваш аккаунт будет удалён за нарушение правил. Подтвердите вход по ссылке и
   введите код из смс: max-verify-account.ru»* — MAX не числится организацией (есть
   только хост `max.ru` в мессенджерах). Чинить: организация MAX (`макс`, `max`,
   домены `max.ru`, `web.max.ru`); `введ* код*` в confirm_data; угроза + «подтвердите» +
   чужая ссылка → «осторожно» без организации.
10. *«Привет! Проголосуй за мою племянницу в конкурсе рисунков, пожалуйста:
    golosovanie-deti.site/anna (нужно подтвердить код из смс)»* — семьи «голосование»
    в словаре нет. Чинить: группа `проголосу*`/`голосовани*`/`конкурс*` + ссылка + код →
    «осторожно».

### 3.6 Оговорки

* Набор написан автором, знающим правила (хоть и вслепую от их текста). Это слабее,

* Числа первого прогона закреплены в `MessageHeldOutTest` как потолок/полы
  (0 ложных, ≥ 50 помечено, ≥ 40 «опасно»): правки словаря могут только улучшать их.

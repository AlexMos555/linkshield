# @cleanway/extension-core

Single source of truth for Cleanway browser extension code. Chrome, Firefox, and Safari all sync from here.

## Why this exists

Before: same popup.html, block-page.js, welcome.html, content scripts — manually copied into three directories. Every popup change required three copies + manual testing that we didn't forget one. In practice: firefox/safari got stale.

**Now:** edit `packages/extension-core/src/...` once, run `scripts/build-extensions.sh`, all three browser builds refresh.

## What DOESN'T live here

Each browser extension dir keeps its own:
- `manifest.json` — different format per browser (MV3 chrome, MV2 firefox, MV3 safari)
- `_locales/` — regenerated by `scripts/build-i18n.py` from `packages/i18n-strings/`
- `overrides/` (optional) — per-flavor file substitutions, see below

## Build

```bash
bash scripts/build-extensions.sh
```

This:
1. Clears `src/`, `public/`, `styles/` in each extension dir
2. Copies from `packages/extension-core/`
3. Applies `extension-{flavor}/overrides/` (if present) on top
4. Re-runs `scripts/build-i18n.py` so locales stay in sync

The Firefox `chrome → browser` alias is no longer text injected by the build: the background is an ES module, so it lives in `src/background/browser-compat.js` (a no-op outside Firefox).

## Background rules

- The background loads as an ES module in all three builds (`"type": "module"`; Chrome 92+, Firefox 112+, Safari 16.4+). Use **static** `import` only — `import()` and `importScripts()` throw in a module service worker. `scripts/test-extension-core.mjs` fails CI if anything the background can reach calls either.
- Feature-check optional APIs (`contextMenus`, `notifications`, `commands`, `action`) before touching them. Yandex Browser on Android, Safari and Firefox each lack some; one unguarded `undefined.addListener` at top level aborts the whole module, link checks included.

Typical iteration:
```bash
# Edit packages/extension-core/src/popup/popup.html
bash scripts/build-extensions.sh
# Reload unpacked extension in Chrome → see changes
```

## Per-flavor overrides

If a specific browser needs a file that differs from the shared version, put it under that extension's `overrides/` directory with the same relative path. `build-extensions.sh` copies overrides AFTER the core sync, so they always win.

Example: Safari needs a different popup stylesheet
```
extension-safari/overrides/src/popup/popup.css  ← this wins over core's popup.css
```

**Rule of thumb:** if you find yourself reaching for overrides, think first if the divergence should actually live in core with a runtime flavor detection (e.g. `typeof browser !== "undefined"`).

## i18n integration

Code in this package uses `chrome.i18n.getMessage("key_name")`. The keys come from the final `_locales/<lang>/messages.json` produced by `scripts/build-i18n.py` from `packages/i18n-strings/`.

**Never** add literal English strings. Always use `chrome.i18n.getMessage` + add the key to `packages/i18n-strings/src/en.json` (and the 9 other locale files).

## Testing

```bash
node scripts/test-extension-core.mjs   # static: trusted hosts, SW module graph, manifests, i18n keys (all trees)
node scripts/test-local-scorer.mjs     # offline scorer table
node scripts/test-extension-sw.mjs     # real headless Chromium: loads extension/ + extension-safari/ unpacked
```

`test-extension-sw.mjs` needs `playwright` + `tweetnacl` (repo `node_modules`) and `npx playwright install chromium`. It points the extension at a local mock API and blocks `*.cleanway.ai`, so it never touches production. It proves the threat counter, Family Hub fan-out (decrypted on the other side), the Family Hub poller, the 30-day history prune, the exact-host trust list and Russian content-script warnings. Firefox (MV2) can't load in Chromium; it is covered by the static checks only — still load it by hand in Firefox before a release.

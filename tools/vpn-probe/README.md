# Видит ли исключённое приложение VPN Cleanway? Эксперимент на эмуляторе

*27.09.2026. Эмулятор Android 15 (API 35, `sdk_gphone64_arm64`, emulator-5554). Физический телефон не трогали.*

## Коротко

- **Исключение из туннеля (`addDisallowedApplication`) скрывает VPN от проверки, которой, по разбору InterSecLab, пользуется МАКС**: `getNetworkCapabilities(activeNetwork).hasTransport(TRANSPORT_VPN)` у исключённого приложения даёт `false`. Также пропадают VPN в callback'е сети по умолчанию, в `LinkProperties` активной сети (DNS 10.0.0.1, `tun0`) и в VPN-запросе `NetworkRequest`. DNS исключённого приложения идёт мимо щита: заблокированный Cleanway домен у него открывается.
- **Исключение НЕ скрывает VPN от трёх проверок.** Их видит любое приложение, исключённое или нет:
  1. `ConnectivityManager.getAllNetworks()`: в списке есть сеть с `TRANSPORT_VPN` (интерфейс `tun0`, DNS 10.0.0.1, `VpnTransportInfo`);
  2. устаревший `getNetworkInfo(TYPE_VPN)` / `getAllNetworkInfo()`: `VPN CONNECTED`, причём в поле `extra` стоит **имя пакета владельца VPN** (`VPN:ai.cleanway.app.dev`), то есть любое приложение может узнать, что VPN именно у Cleanway;
  3. `NetworkInterface.getNetworkInterfaces()`: интерфейс `tun0` виден и поднят (`up=true`, `p2p=true`).
- `/proc/net/*` и `/sys/class/net` на Android 15 приложению недоступны вообще, и с targetSdk 34, и с 28. `net.dns1` пуст во всех случаях. По этим признакам VPN не виден.
- Итог для МАКС: если он действительно смотрит только `TRANSPORT_VPN` активной сети (так пишет InterSecLab), исключение ему поможет. Приложения, которые перебирают все сети или интерфейсы, продолжат жаловаться. По данным RKS Global, таких 13 из 30 (они «видят VPN-интерфейс даже при исключении из туннеля»). Наш замер механизм подтверждает. **Проверить сам МАКС можно только на телефоне с российской SIM и аккаунтом МАКС.**

## Как мерили

- **Зонд** (`src/ai/cleanway/probe/MainActivity.java`, собран голым SDK: `build.sh`). По кнопке или по `am start … --ez auto true --es label X` пишет каждый признак в logcat (тег `CwProbe`) и в файл. Три пакета с одним кодом:
  - `ai.cleanway.probe`: targetSdk 34, есть иконка;
  - `ai.cleanway.probe.legacy`: targetSdk 28, старый SELinux-домен, без ограничений видимости пакетов;
  - `ai.cleanway.probe.hidden`: targetSdk 34, без иконки, поэтому невидим для Cleanway.
  Ещё две заглушки с тем же кодом носят имена пакетов из списка: `ru.oneme.app` («MAX (test stub)») проверяет список по умолчанию, `ru.ozon.app.android` проверяет «подсказки». Это эмуляторные заглушки, а не настоящие приложения.
- **Cleanway**: debug-сборка ветки `feat/vpn-app-exclusion` с `applicationIdSuffix ".dev"`. Она ставится рядом с релизом 1.0.3, JS встроен, Metro не нужен. Исключения применяет сам механизм из PR: список по умолчанию, выбор человека и `addDisallowedApplication`.
- Какие UID покрывает VPN, проверяли по `dumpsys connectivity` (`Uids: <{…}>` у VPN-сети).
- Проверка «туннель обойдён»: резолв `027xrf.com` и `023trafficaccidentlawyer.com`. Оба есть в живом списке Cleanway (хэш совпал 27.09) и резолвятся в публичном DNS. В туннеле получается NXDOMAIN (блок), вне туннеля имя резолвится.

Строка 8 от туннеля не зависит. Приложение с targetSdk 34, у которого есть только `<queries>`, Cleanway не находит: наш `VpnService` объявлен `exported=false`. Приложение с targetSdk ≤ 29 (без ограничений видимости) или с `QUERY_ALL_PACKAGES` находит Cleanway как «VPN-клиент», даже когда щит выключен. RKS пишет, что семь приложений собирают список установленных VPN-клиентов. Против этого исключение бессильно.

Для legacy (t28) и hidden (t34, без иконки) результаты совпали с основным зондом по всем строкам, кроме 8.

## Что ещё выяснилось (и повлияло на код)

1. **Android 15 не бросает `NameNotFoundException` из `addDisallowedApplication` для неустановленных пакетов.** Первая сборка «применила» все 12 пакетов по умолчанию (`applied=12 not_installed=0`) на эмуляторе, где их нет. VPN при этом покрывал UID `0-99999`, система неизвестные имена просто пропустила. Поэтому «установлен ли пакет» теперь проверяется явно (`AppExclusions.isInstalled`), а исключение ловится как запасной вариант.
2. **Системе видимость пакета не нужна.** Невидимый для Cleanway `ai.cleanway.probe.hidden` система исключила, когда имя передали в builder (UID 10222 выпал из диапазона). Наш код теперь такие пакеты не передаёт: исключаем только то, что можем показать человеку в Настройках. Поэтому каждый пакет из списка по умолчанию объявлен в `<queries>`, а выбор идёт из приложений с иконкой.
3. **Смена списка применяется на лету** через повторный `establish()`, но **с коротким разрывом**, а не бесшовно. Когда меняется список исключённых приложений, Android не может передать VPN-сеть на месте. В системном журнале на каждое переключение пишется `Vpn: Handover not possible due to changes to allowed/denied apps`. Система регистрирует новую VPN-сеть и сначала снимает старую. Мы измерили пять переключений от снятия UID-диапазонов старой сети в netd до добавления диапазонов новой: 152, 366, 246, 211 и 443 мс. В это окно происходит три вещи:
   - у приложений в туннеле нет VPN-сети, поэтому их DNS идёт напрямую в сеть, без фильтра;
   - все приложения получают события VPN «потеряна» → «доступна», а для `TYPE_VPN` уходит broadcast `DISCONNECTED`;
   - система закрывает живые TCP-соединения приложений в туннеле (`Destroyed live tcp sockets for uids=…`), и им приходится переподключаться.

   Снимок `dumpsys` в 11:17:22 (`dumpsys-max-refiltered.txt`) попал как раз в такое окно: VPN-сети в нём нет. Всё это случается, только когда человек меняет список или когда ставится или удаляется приложение из списка. После переключения в логах `tunnel_reestablished`, VPN-сеть получает новый id и UID меняются. Остаются ровно один поток `Cleanway-DNS` и один `tun`. Canary после этого проходит: на главном экране «Работает прямо сейчас».
4. **Установка и удаление приложения из списка тоже применяются сами**, без перезапуска щита, с тем же коротким разрывом (см. п. 3). Заглушку МАКС поставили при включённом щите, и её UID сразу исключился. После удаления UID вернулся в туннель. Повторного использования UID мы не видели: после удаления 10224 следующие установки получили 10225 и 10226. После перезагрузки туннель строится заново, и UID ищутся снова. Обработка удаления нужна для порядка: туннель исключает ровно то, что показано в Настройках. Заодно она страхует на случай, если какая-то версия Android отдаёт освободившийся UID раньше.
5. Попутно (не из-за этого PR): у VPN-сети Cleanway есть маршрут `::/0 unreachable`. У приложений внутри туннеля нет IPv6, работает откат на IPv4. Мы это не вызвали, но полезно знать.

## Как повторить

```bash
bash tools/vpn-probe/build.sh                      # собирает APK голым SDK (JDK 17, build-tools 35)
adb -s emulator-5554 install -r tools/vpn-probe/probe.apk        # и probe-legacy / probe-hidden
ADB_SERIAL=emulator-5554 tools/vpn-probe/run.sh no-vpn            # щит выключен
ADB_SERIAL=emulator-5554 tools/vpn-probe/run.sh shield-on         # щит включён
# Cleanway → Настройки → «Приложение просит отключить VPN?» → VPN probe
ADB_SERIAL=emulator-5554 tools/vpn-probe/run.sh probe-excluded
```

Полный отчёт каждого запуска лежит в `raw/<label>--<package>.txt` (в git не попадает) и в logcat с тегом `CwProbe`. `run.sh` в конце печатает UID-диапазоны VPN-сети: UID исключённого приложения из них выпадает.

`stub-max.apk` и `stub-ozon.apk` — эмуляторные заглушки с именами пакетов из списка. Они нужны, чтобы проверить список по умолчанию и подсказки. На телефон с настоящими МАКС или Ozon их не ставить. Поверх настоящего приложения заглушка не встанет: она подписана другим ключом, и `adb install -r` вернёт `INSTALL_FAILED_UPDATE_INCOMPATIBLE`. Но если настоящее приложение удалить, заглушка займёт его место, и Cleanway примет её за настоящий МАКС или Ozon. Зонд проверяет домены `027xrf.com` и `023trafficaccidentlawyer.com`. 27.09.2026 оба были в списке Cleanway и резолвились публично. Со временем их нужно менять на свежие.

**Полевой тест, которого здесь нет:** настоящий МАКС, Госуслуги и Сбер на телефоне с российской SIM. МАКС ограничивает российские номера на зарубежных IP, поэтому эмулятор и тестовый A16 этот тест не заменят.
